1. `git init` (if not already) → commit everything as `pre-migration`.
2. Executor writes its own STATE.md brain-dump: in-flight work, open
   threads, anything known but not yet in a report. Session memory dies
   with the session; disk survives.
3. Path audit: no absolute paths in scripts; everything relative to a
   PROJECT_ROOT.
4. Copy the chat-side artifacts into the repo: 07-RULEBOOK.md,
   hand_check_verdicts_v1.json, the v1.3 prompt package (prompts, config,
   START_CHECKLIST, pack seeds), loop_protocol_sim.py,
   checker_quality_sim.py, and this HANDOFF.md.
5. Point the Cowork project at the repo folder. Commit `post-migration`;
   `git diff pre-migration post-migration` on tracked content should be
   additions only.
6. **Arrival verification (the checksum)**: run every fixture in the new
   home — canon neutrality vs captured outputs, matcher fixture 11/11,
   meter fixture, probes 40/40 under the current stack — and confirm the
   sentinel reads exactly 338. All green ⇒ the migration provably lost
   nothing. Any red ⇒ stop and diff before proceeding.
7. NEVER run `--invalidate` during migration. The sentinel firing on a
   count mismatch is the alarm working, not an obstacle.
